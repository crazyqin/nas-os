## 1. GPU 直通管理

### 功能概述

将物理 GPU 设备直接分配给虚拟机或容器，绕过宿主机虚拟化层，实现接近原生的 GPU 计算性能。适用于 AI 推理、视频转码、深度学习训练等 GPU 密集型场景。

### 使用说明

#### 启用 GPU 直通

1. 进入 **系统设置 → 硬件管理 → GPU 直通**
2. 系统自动检测可用 GPU 设备（NVIDIA/AMD/Intel）
3. 选择目标 GPU，点击 **绑定 VFIO 驱动**
4. 重启系统使驱动绑定生效

#### 分配 GPU 给虚拟机

1. 编辑虚拟机配置 → **硬件 → 添加 PCI 设备**
2. 选择已绑定 VFIO 的 GPU 设备
3. 保存配置并启动虚拟机
4. 虚拟机内安装对应 GPU 驱动即可使用

#### 分配 GPU 给容器

1. 编辑容器配置 → **资源限制 → GPU 分配**
2. 选择 GPU 设备，设置显存限制
3. 容器内通过 `/dev/vfio/` 访问 GPU

### 配置方法

```bash
# 通过 API 启用 GPU 直通
curl -X POST /api/v1/gpu-passthrough/enable \
  -d '{"device_id": "0000:01:00.0", "driver": "vfio-pci"}'

# 查询 GPU 状态
curl /api/v1/gpu-passthrough/devices

# 分配 GPU 给 VM
curl -X POST /api/v1/gpu-passthrough/assign \
  -d '{"device_id": "0000:01:00.0", "target_type": "vm", "target_id": "vm-001"}'
```

### 注意事项

- **IOMMU 支持**：需在 BIOS 中启用 VT-d（Intel）或 AMD-Vi（AMD）
- **驱动冲突**：绑定 VFIO 前需确保宿主机未加载 GPU 驱动（如 nvidia.ko）
- **多 GPU 场景**：建议保留至少一个 GPU 给宿主机显示输出
- **热插拔**：GPU 绑定/解绑需重启生效，不支持热插拔
- **兼容性**：已验证 NVIDIA Tesla/RTX 系列、AMD Radeon Pro 系列、Intel Arc 系列

## 2. 远程备份引擎

### 功能概述

企业级远程备份引擎，支持将数据加密备份到多种远程存储目的地，包括 S3 兼容存储、FTP/SFTP 服务器、WebDAV 服务等。支持增量备份、版本管理和自动调度。

### 使用说明

#### 配置备份目的地

1. 进入 **备份管理 → 远程备份 → 目的地管理**
2. 点击 **添加目的地**，选择类型：
   - **S3 兼容**：AWS S3、MinIO、阿里云 OSS、腾讯云 COS
   - **FTP/SFTP**：标准 FTP 或 SSH 文件传输
   - **WebDAV**：WebDAV 协议存储
3. 填写连接信息（端点、认证、桶/路径）
4. 点击 **测试连接** 验证配置

#### 创建备份任务

1. 进入 **备份管理 → 远程备份 → 任务管理**
2. 点击 **新建任务**：
   - **源路径**：选择要备份的文件夹
   - **目的地**：选择已配置的远程目的地
   - **备份策略**：全量/增量/差异
   - **调度计划**：每日/每周/自定义 Cron
   - **加密设置**：AES-256 加密，设置加密密钥
   - **保留策略**：保留最近 N 个版本或 N 天
3. 保存并启动任务

#### 恢复数据

1. 进入 **备份管理 → 远程备份 → 恢复**
2. 选择备份任务和版本
3. 选择恢复目标路径
4. 点击 **开始恢复**

### 配置方法

```bash
# 添加 S3 备份目的地
curl -X POST /api/v1/remote-backup/destinations \
  -d '{
    "name": "aws-primary",
    "type": "s3",
    "endpoint": "s3.amazonaws.com",
    "bucket": "nas-backup",
    "access_key": "AKIA...",
    "secret_key": "...",
    "region": "us-east-1",
    "encryption": true
  }'

# 创建备份任务
curl -X POST /api/v1/remote-backup/tasks \
  -d '{
    "name": "daily-docs-backup",
    "source": "/data/documents",
    "destination_id": "aws-primary",
    "strategy": "incremental",
    "schedule": "0 2 * * *",
    "encryption_key": "...",
    "retention_days": 90
  }'

# 手动触发备份
curl -X POST /api/v1/remote-backup/tasks/{task_id}/run
```

### 注意事项

- **加密密钥**：加密密钥丢失将导致备份无法恢复，请妥善保管
- **带宽控制**：支持设置上传带宽限制，避免影响正常业务
- **断点续传**：大文件备份支持断点续传，网络中断无需重传
- **校验验证**：每次备份完成后自动校验数据完整性
- **并发限制**：默认最多同时运行 3 个备份任务，可在设置中调整

## 3. 文件自助恢复门户

### 功能概述

为普通用户提供自助式文件恢复界面，用户可以浏览历史备份版本，按时间点、文件名搜索，自行恢复误删或修改的文件，无需管理员介入。

### 使用说明

#### 访问恢复门户

1. 通过浏览器访问 `https://<nas-ip>:8443/restore`
2. 使用普通用户账号登录（无需管理员权限）
3. 进入文件恢复界面

#### 浏览和搜索

1. **按时间浏览**：在时间轴上选择日期，查看该时间点的文件快照
2. **按文件搜索**：输入文件名或路径关键词，搜索历史版本
3. **按版本对比**：选择两个时间点，对比文件差异

#### 恢复文件

1. 找到目标文件，点击 **预览** 查看内容
2. 确认后点击 **恢复**：
   - **恢复到原位置**：覆盖当前文件（会创建当前版本备份）
   - **恢复到指定位置**：选择其他目录保存
   - **下载到本地**：直接下载文件到客户端
3. 批量选择多个文件/文件夹一次性恢复

### 配置方法

```bash
# 启用文件自助恢复门户
curl -X POST /api/v1/self-restore/config \
  -d '{"enabled": true, "allow_download": true, "max_versions": 100}'

# 管理员设置用户恢复权限
curl -X POST /api/v1/self-restore/permissions \
  -d '{"user_id": "user01", "paths": ["/data/documents", "/data/photos"], "max_restore_size_mb": 1024}'

# 查询可用备份版本
curl /api/v1/self-restore/versions?path=/data/documents/report.docx
```

### 注意事项

- **权限控制**：用户只能恢复自己有读权限的目录下的文件
- **版本数量**：默认保留最近 100 个版本，可通过配置调整
- **恢复日志**：所有恢复操作均记录审计日志
- **存储空间**：恢复操作不额外占用存储空间（使用 ZFS 快照）
- **并发限制**：每个用户最多同时恢复 5 个任务

## 4. 容器安全扫描

### 功能概述

对 Docker/OCI 容器镜像进行全面安全扫描，检测已知漏洞（CVE）、恶意软件、敏感信息泄露和合规性问题。支持镜像构建时扫描、仓库扫描和运行时监控。

### 使用说明

#### 镜像漏洞扫描

1. 进入 **容器管理 → 安全扫描**
2. 选择扫描目标：
   - **本地镜像**：扫描已拉取的镜像
   - **远程仓库**：扫描 Docker Hub、Harbor 等仓库
   - **构建时扫描**：集成到 CI/CD 流水线
3. 点击 **开始扫描**
4. 查看扫描报告：漏洞列表、严重级别、修复建议

#### 合规策略

1. 进入 **容器管理 → 安全扫描 → 合规策略**
2. 配置安全策略：
   - **漏洞阈值**：禁止部署 Critical/High 级别漏洞的镜像
   - **基础镜像白名单**：仅允许使用指定基础镜像
   - **密钥检测**：禁止镜像中包含硬编码密钥
   - **特权容器检查**：禁止以 root 运行或特权模式
3. 部署时自动检查策略合规性

#### 运行时监控

1. 进入 **容器管理 → 安全扫描 → 运行时监控**
2. 实时监控容器行为：
   - 异常进程检测
   - 文件系统变更监控
   - 网络连接审计
   - 系统调用追踪
3. 发现异常自动告警并可配置自动阻断

### 配置方法

```bash
# 扫描本地镜像
curl -X POST /api/v1/container-security/scan \
  -d '{"image": "nginx:latest", "scan_type": "full"}'

# 查询扫描报告
curl /api/v1/container-security/reports/{scan_id}

# 配置合规策略
curl -X POST /api/v1/container-security/policies \
  -d '{
    "name": "production-policy",
    "max_severity": "medium",
    "allowed_base_images": ["alpine:3.18", "ubuntu:22.04"],
    "deny_privileged": true,
    "detect_secrets": true
  }'

# 启用运行时监控
curl -X POST /api/v1/container-security/runtime/enable \
  -d '{"container_id": "abc123", "monitor_filesystem": true, "monitor_network": true}'
```

### 注意事项

- **漏洞数据库**：基于 CVE/NVD 数据库，每日自动更新
- **扫描耗时**：大型镜像（>1GB）扫描可能需要数分钟
- **性能影响**：运行时监控会带来约 2-5% 的性能开销
- **误报处理**：支持标记误报，后续扫描自动跳过
- **CI/CD 集成**：提供 CLI 工具，可集成到 Jenkins/GitHub Actions/GitLab CI

## 5. ZFS 池扩容向导

### 功能概述

在线扩展 ZFS 存储池容量，支持向现有 RAID-Z vdev 添加新磁盘（RAID-Z Expansion），无需重建存储池，数据自动在新旧磁盘间再平衡。

### 使用说明

#### 扩容流程

1. 进入 **存储管理 → ZFS 池管理 → 扩容向导**
2. 选择要扩容的存储池
3. 向导自动检测：
   - 当前 vdev 拓扑（mirror/RAID-Z1/Z2/Z3）
   - 可用空闲磁盘
   - 扩容后容量预估
4. 选择新磁盘，确认扩容方案
5. 点击 **开始扩容**
6. 系统显示：
   - 预计扩容时间
   - 数据再平衡进度
   - 当前 I/O 性能影响评估

#### 进度监控

1. 扩容过程中实时显示进度百分比
2. 预计剩余时间根据实际 I/O 速度动态调整
3. 扩容期间存储池保持在线可用
4. 完成后发送通知

### 配置方法

```bash
# 查询存储池信息
curl /api/v1/zfs-pools/{pool_id}

# 启动扩容
curl -X POST /api/v1/zfs-pools/{pool_id}/expand \
  -d '{
    "new_disks": ["/dev/sdd", "/dev/sde"],
    "expand_type": "raidz",
    "auto_rebalance": true
  }'

# 查询扩容进度
curl /api/v1/zfs-pools/{pool_id}/expand/status

# 暂停扩容（限速运行）
curl -X POST /api/v1/zfs-pools/{pool_id}/expand/throttle \
  -d '{"max_iops": 1000, "max_bandwidth_mbps": 200}'
```

### 注意事项

- **磁盘兼容性**：新磁盘容量应 ≥ 现有 vdev 中最小磁盘容量
- **RAID-Z Expansion**：需要 OpenZFS 2.3.0+ 支持
- **性能影响**：扩容期间 I/O 性能可能下降 10-30%，建议业务低峰期操作
- **不可逆操作**：扩容完成后无法移除添加的磁盘
- **快照兼容**：扩容期间快照功能正常可用
- **电源保护**：扩容过程断电可能导致数据不一致，建议连接 UPS

## 6. RDMA 存储加速

### 功能概述

利用 RDMA（远程直接内存访问）技术实现超低延迟、高吞吐量的存储网络传输。自动检测 RDMA 网卡，为 iSCSI 和 NFS 存储协议提供内核旁路加速。

### 使用说明

#### 自动检测与启用

1. 进入 **网络管理 → RDMA 存储加速**
2. 系统自动检测：
   - RDMA 网卡（RoCE/iWARP/InfiniBand）
   - 网络拓扑和交换机支持
   - 对端 RDMA 能力
3. 一键启用 RDMA 加速

#### iSCSI RDMA 配置

1. 进入 **存储管理 → iSCSI → 传输设置**
2. 选择 **iSER（iSCSI Extensions for RDMA）** 传输模式
3. 配置 RDMA 网卡绑定和 IP 地址
4. 重启 iSCSI Target 服务

#### NFS RDMA 配置

1. 进入 **共享管理 → NFS → 高级设置**
2. 启用 **NFS over RDMA**
3. 配置 RDMA 端口和传输类型
4. 重启 NFS 服务

### 配置方法

```bash
# 查询 RDMA 设备
curl /api/v1/rdma-acceleration/devices

# 启用 RDMA 加速
curl -X POST /api/v1/rdma-acceleration/enable \
  -d '{
    "device": "mlx5_0",
    "protocol": "roce",
    "ip_address": "192.168.100.1",
    "services": ["iscsi", "nfs"]
  }'

# 性能调优
curl -X POST /api/v1/rdma-acceleration/tune \
  -d '{
    "queue_depth": 256,
    "mtu": 4096,
    "interrupt_coalescing": true,
    "numa_aware": true
  }'

# 查询 RDMA 性能统计
curl /api/v1/rdma-acceleration/stats
```

### 注意事项

- **硬件要求**：需要支持 RDMA 的网卡（Mellanox ConnectX 系列、Broadcom NetXtreme-E 等）
- **交换机要求**：RoCE 需要支持 PFC（优先流控）的交换机
- **TCP 回退**：RDMA 不可用时自动回退到 TCP，不影响正常服务
- **NUMA 绑定**：建议 RDMA 网卡和 CPU 在同一 NUMA 节点，减少跨节点延迟
- **固件版本**：确保 RDMA 网卡固件为最新版本
- **性能提升**：典型场景下延迟降低 50-70%，吞吐量提升 30-50%

## 📦 升级指南

### 从 v2.534.x 升级

1. 备份当前配置：`nas-os backup config`
2. 更新到 v2.535.0：`nas-os update`
3. 运行数据库迁移：`nas-os migrate`
4. 重启服务：`nas-os restart`
5. 验证新功能：访问管理界面确认各模块正常

### 系统要求

- Linux Kernel ≥ 5.15（RDMA 加速需要 ≥ 6.0）
- OpenZFS ≥ 2.3.0（ZFS 池扩容需要）
- Docker ≥ 24.0（容器安全扫描需要）
- 至少 4GB RAM（建议 8GB+）
