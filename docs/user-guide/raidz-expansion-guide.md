**版本**: v2.322.0 | **创建日期**: 2026-03-30 | **状态**: 规划中

## 功能概述

RAIDZ扩展（存储池在线扩容）是一项正在规划的功能，将允许您向现有存储阵列逐个添加硬盘，实现增量扩容，无需重建整个存储池。

### 为什么需要RAIDZ扩展？

**传统扩容方式的问题**：
- 需要新建更大的存储池
- 数据需要完整迁移备份
- 扩容过程业务中断时间长
- 空间利用率提升成本高

**RAIDZ扩展的优势**：
- ✅ 单盘逐个添加，降低扩容门槛
- ✅ 扩容过程存储池保持可用
- ✅ 原有冗余级别不变（RAID1→RAID1，RAID10→RAID10）
- ✅ 数据自动重分布，无需手动迁移
- ✅ 支持中断恢复，可重启后继续

## 使用场景

### 场景1：家庭用户扩容

**现状**：
- 4盘位NAS，使用3块4TB硬盘组成RAID1
- 当前容量：6TB
- 数据增长：需要扩容至12TB

**扩容方案**（规划功能）：
1. 购买1块新4TB硬盘
2. 通过WebUI"存储池扩容"功能添加
3. 系统自动执行数据重分布
4. 扩容完成，容量翻倍至12TB

**预计耗时**：
- 6TB数据重分布：约2-4小时（HDD）
- 业务中断：0分钟（在线操作）

### 场景2：小型工作室扩容

**现状**：
- 8盘位NAS，使用6块8TB硬盘组成RAID10
- 当前容量：24TB
- 业务增长：需要扩容至32TB

**扩容方案**：
1. 添加2块8TB硬盘
2. 保持RAID10冗余级别
3. 自动数据重分布
4. 容量增加8TB

### 场景3：技术爱好者双引擎

**需求**：
- 希望体验ZFS级别的数据完整性
- 同时保持btrfs的灵活性

**解决方案**（中期规划）：
1. 启用ZFS可选后端
2. 使用存储池迁移工具
3. 享受原生RAIDZ扩展支持

## 技术原理（简化说明）

### 数据重分布过程

当添加新硬盘时，系统会：

1. **识别新设备**：检测新硬盘容量和状态
2. **启动重分布**：将现有数据重新条带化
3. **均衡写入**：新数据写入使用新条带宽度
4. **进度监控**：实时显示扩容进度
5. **完成验证**：校验数据完整性

### 冗余级别保持

| 原阵列 | 扩容后阵列 | 说明 |
|--------|-----------|------|
| RAID1（2盘） | RAID1（3盘） | 保持双副本冗余 |
| RAID10（4盘） | RAID10（6盘） | 保持镜像+条带 |
| RAIDZ1（3盘） | RAIDZ1（4盘） | 保持单盘冗余（ZFS后端） |

## 使用流程（规划）

### WebUI扩容操作

**步骤预览**：

1. **进入存储管理**
   - 打开"存储池"页面
   - 选择需要扩容的存储池

2. **检查扩容条件**
   - 系统自动检测可用硬盘
   - 显示容量匹配建议
   - 预估扩容时间和结果

3. **添加新硬盘**
   - 选择要添加的硬盘
   - 确认扩容参数
   - 点击"开始扩容"

4. **监控进度**
   - 实时进度百分比
   - 预计剩余时间
   - 性能影响提示

5. **完成验证**
   - 数据完整性校验
   - 新容量确认
   - 建议执行一次快照

### 命令行操作（高级用户）

**btrfs扩容命令**（规划封装）：

```bash
# 1. 添加新设备
btrfs device add /dev/sdX /mnt/pool

# 2. 启动数据重分布
btrfs balance start /mnt/pool

# 3. 监控进度
btrfs balance status /mnt/pool

# 4. 完成后检查
btrfs filesystem usage /mnt/pool
```

## 注意事项与限制

### 当前技术限制

基于btrfs的限制（短期版本）：

| 限制项 | 说明 | 建议 |
|--------|------|------|
| RAID5/6不稳定 | 官方标记为不稳定 | 使用RAID1/RAID10 |
| Balance过程长 | 大数据量重分布耗时 | 后台调度+限速 |
| 性能影响 | 重分布过程IO负载高 | 避免高峰期操作 |

### 最佳实践建议

**扩容前检查**：
- ✅ 确认存储池健康状态良好
- ✅ 确认有足够空间存放临时数据
- ✅ 建议在业务低峰期执行
- ✅ 执行前创建快照备份

**扩容过程监控**：
- ✅ 观察系统温度和负载
- ✅ 避免同时执行其他IO密集任务
- ✅ 监控硬盘健康状态

**扩容后验证**：
- ✅ 检查数据完整性
- ✅ 确认新容量可用
- ✅ 执行一次完整快照
