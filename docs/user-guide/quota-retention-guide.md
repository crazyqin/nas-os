# 智能配额与数据保留策略使用指南

> **版本**: v2.480.0  
> **更新日期**: 2026-05-02

---

## 概述

NAS-OS 提供智能配额管理和数据保留策略引擎，帮助管理员合理分配存储资源、自动管理数据生命周期。

---

## 智能配额管理

### 配额类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 用户配额 | 限制单个用户的存储用量 | 个人 NAS、多用户环境 |
| 共享文件夹配额 | 限制共享目录的总容量 | 部门共享、项目空间 |
| 组配额 | 限制用户组的总容量 | 团队、部门级限制 |
| 弹性配额 | 基于使用模式动态调整 | 混合负载环境 |

### 配置用户配额

1. 进入「存储」→「配额管理」→「用户配额」
2. 选择用户
3. 设置配额参数：

| 参数 | 说明 |
|------|------|
| 硬限制 | 超过后无法写入 |
| 软限制 | 超过后发出警告，宽限期内仍可写入 |
| 宽限期 | 软限制后的宽限时间（默认 7 天） |
| 告警阈值 | 达到百分比时发送通知（默认 80%） |

### 弹性配额

智能配额根据使用模式自动调整：
- **工作日白天** - 给办公用户更多配额
- **夜间** - 给备份任务更多空间
- **周末** - 给媒体应用更多配额

```yaml
elastic_quota:
  user: zhangsan
  base_quota: 500GB
  rules:
    - condition: "weekday AND 09:00-18:00"
      boost: 1.5x    # 工作时间配额 750GB
    - condition: "weekend"
      boost: 2.0x    # 周末配额 1TB
```

## 数据保留策略引擎

### 策略类型

| 策略 | 说明 |
|------|------|
| 时间保留 | 按文件年龄自动清理 |
| 版本保留 | 保留最近 N 个版本 |
| 空间保留 | 空间不足时自动清理旧数据 |
| 合规保留 | 法规要求的最低保留期 |
| 智能保留 | 基于访问频率决定保留 |

### 创建保留策略

1. 进入「存储」→「数据保留」→「策略管理」
2. 点击「新建策略」
3. 配置策略规则：

```yaml
retention_policy:
  name: "日志保留策略"
  target: "/data/logs/"
  rules:
    - type: time
      retention_days: 90        # 保留90天
      action: delete            # 超期删除
    - type: time
      retention_days: 30
      action: archive           # 30天后归档到冷存储
  exclusions:
    - pattern: "*.important"    # 重要文件排除
    - pattern: "audit/**"       # 审计日志保留
```

### 合规保留模式

满足法规要求的数据保留：
- **WORM（一次写入多次读取）** - 数据写入后不可修改/删除
- **法定保留期** - 最低保留期限，不可提前删除
- **审计追踪** - 记录所有数据访问和操作

### 保留策略与配额联动

配额管理与保留策略可以协同工作：
1. 用户接近配额上限时，优先清理过期数据
2. 保留策略清理释放的空间不计入配额使用
3. 合规保留的数据不受配额限制

## 监控与报告

### 配额使用报告

- 各用户/组配额使用率排名
- 配额使用趋势（日/周/月）
- 超限告警历史
- 弹性配额调整记录

### 保留策略执行报告

- 策略执行状态
- 清理/归档的数据量
- 合规保留数据统计
- 策略冲突告警

---

## 最佳实践

1. **渐进式配额** - 先设软限制观察，再逐步收紧
2. **保留策略先于删除** - 使用归档替代直接删除
3. **合规优先** - 法规保留期不可妥协
4. **定期审计** - 检查策略执行是否符合预期
5. **通知用户** - 配额变更前提前通知
