## 功能概述

### 什么是按需唤醒？

按需唤醒（Disk Spin Down）是一种节能策略：硬盘空闲时自动休眠，访问时自动唤醒。可降低功耗约 70%（活跃 10W → 休眠 1W）。

### 适用场景

| 场景 | 推荐程度 | 说明 |
|------|----------|------|
| 影音库存储盘 | ✅ 推荐 | 低频访问，节能明显 |
| 归档备份盘 | ✅ 推荐 | 仅备份时激活 |
| 冷存储数据 | ✅ 推荐 | 极少访问 |
| 系统盘 | ❌ 不推荐 | 永不休眠 |
| 数据库盘 | ❌ 不推荐 | 事务完整性需求 |
| 监控盘 | ❌ 不推荐 | 勒索防护需实时监控 |

## 快速配置

### WebUI 开启

1. 「硬件管理」→ 「磁盘电源」
2. 选择磁盘，配置策略：
   - **休眠阈值**: 空闲多少分钟后休眠（默认 30min）
   - **唤醒策略**: SMART检测后唤醒（推荐开启）
   - **并发限制**: 最大同时唤醒数（默认 3）

### 配置示例

```yaml
disk_power:
  # 休眠策略
  spin_down:
    idle_minutes: 30       # 空闲30分钟休眠
    smart_check_before_wake: true  # 唤醒前SMART检测
    
  # 安全边界 - 永不休眠
  never_sleep:
    - /dev/sda  # 系统盘
    - /dev/sdb  # 数据库盘
    
  # 服务依赖 - 运行时保持活跃
  service_lock:
    - smb-server
    - jellyfin
```

## 安全边界配置

### ⚠️ 必须不休眠的磁盘

| 类型 | 原因 |
|------|------|
| 系统盘 | 系统稳定性 |
| ZFS 缓存盘(L2ARC/SLOG) | 缓存性能 |
| 数据库数据盘 | 事务完整性 |
| 勒索防护监控盘 | 实时检测能力 |
| 快照策略依赖盘 | 数据保护连续性 |

### WebUI 配置路径

「硬件管理」→ 「磁盘电源」→ 「安全边界」

勾选需要「永不休眠」的磁盘。

## 服务依赖管理

### 关键服务与磁盘绑定

| 服务 | 建议绑定磁盘 | 策略 |
|------|--------------|------|
| SMB/NFS 共享 | 所有数据盘 | 服务运行时保持活跃 |
| Jellyfin/Plex | 媒体盘 | 可休眠，播放时唤醒 |
| 备份服务 | 备份盘 | 任务时唤醒 |
| 勒索防护 | 监控盘 | **永不休眠** |

### 配置方法

「硬件管理」→ 「磁盘电源」→ 「服务依赖」

添加服务与磁盘绑定关系，选择策略：
- **keep_active**: 服务运行时磁盘保持活跃
- **wake_on_demand**: 任务时唤醒

## 快照窗口保护

### 什么是快照窗口锁定？

定时快照创建时，磁盘必须活跃。nas-os 在快照窗口自动唤醒并锁定磁盘。

### 自动行为

1. 快照创建前 5 分钟唤醒相关磁盘
2. 快照期间锁定磁盘不休眠
3. 快照完成后释放锁定

### 配置

```yaml
snapshot_power_integration:
  enabled: true
  wake_window_minutes: 5    # 提前唤醒时间
  lock_duration_seconds: 60 # 锁定时长
```

## 勒索防护集成

### ⚠️ 最高优先级安全设计

勒索防护监控的磁盘 **必须永不休眠**，否则：
- 无法实时监控文件变更
- 勒索攻击时无法触发告警
- 无法创建紧急保护快照

### 自动联动机制

| 事件 | 自动动作 |
|------|----------|
| 启动勒索监控 | 锁定监控盘为活跃 |
| 检测到威胁 | 唤醒所有盘 + 创建紧急快照 |
| 安全响应期间 | 全局锁定禁止休眠 |

## 最佳实践

### ✅ 推荐做法

- 影音盘、备份盘启用休眠
- 系统盘、缓存盘永不休眠
- 勒索监控盘保持活跃
- 配置 SMART 检测后唤醒
- 设置并发唤醒限制（≤3）

### ⚠️ 避免的常见错误

| 错误 | 后果 |
|------|------|
| 监控盘启用休眠 | 勒索防护失效 |
| 快照盘休眠 | 定时快照失败 |
| SMB盘休眠 | 用户访问超时断开 |
| 并发唤醒过多 | 电源浪涌风险 |

## 监控与告警

### Prometheus 指标

```promql
disk_power_state{device="/dev/sdb"} 1  # 0=active, 1=standby, 2=sleep
disk_power_wake_count{device="/dev/sdb"} 45
disk_power_spin_down_count{device="/dev/sdb"} 38
disk_power_wake_failed{device="/dev/sdb"} 0
```

### 告警配置

| 告警类型 | 触发条件 |
|----------|----------|
| 唤醒失败 | 连续3次唤醒失败 |
| SMART异常唤醒 | SMART检测后拒绝唤醒 |
| 异常休眠模式 | 短时间内频繁休眠唤醒 |
| 安全边界违反 | 监控盘意外休眠 |

## 常见问题

### Q1: 休眠后访问文件需要多久？

唤醒时间约 5-15 秒。期间：
- SMB 可能超时（可调整超时配置）
- Jellyfin 可能缓冲中断（建议加大缓冲）

### Q2: 多盘同时唤醒安全吗？

不安全。nas-os 限制并发唤醒数：
- 默认最多 3 盘同时唤醒
- 磁盘间间隔 500ms
- 防止电源浪涌

### Q3: 勒索监控盘为什么不能休眠？

监控盘休眠时：
- 无法实时检测文件加密行为
- 无法创建紧急快照
- 诱饵文件失效
- 监控盲区可能导致数据损失

## API 参考

### 获取磁盘电源状态

```bash
GET /api/v1/hardware/disk-power/status
```

响应：
```json
{
  "disks": [
    {
      "device": "/dev/sdb",
      "state": "standby",
      "idle_minutes": 45,
      "wake_count": 38
    }
  ]
}
```

### 配置休眠策略

```bash
POST /api/v1/hardware/disk-power/config
{
  "idle_minutes": 30,
  "never_sleep": ["/dev/sda"],
  "service_lock": ["smb-server"]
}
```
