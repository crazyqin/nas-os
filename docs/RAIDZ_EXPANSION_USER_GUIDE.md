## 功能概述

### 什么是RAIDZ扩展？

RAIDZ扩展（RAIDZ Expansion）是OpenZFS 2.3引入的革命性特性，允许您向现有RAIDZ存储阵列**逐个添加磁盘**，实现存储池的**渐进式在线扩容**。

### 核心价值

传统ZFS扩容存在两大痛点：

| 传统方式 | RAIDZ扩展方式 |
|----------|---------------|
| 成组扩容（RAIDZ2需加一组5-6盘） | 单盘增量扩容 |
| 扩容成本成倍增加 | 扩容成本降低80%+ |
| 需新建存储池 | 原池在线扩容 |
| 数据需完整迁移 | 数据自动重分布 |

**示例对比**：
```
传统扩容：5盘RAIDZ2 → 需再加5-6盘（10-11盘总量，成本翻倍）
RAIDZ扩展：5盘RAIDZ2 → 单盘扩容至6盘（增量成本最优）
```

## 核心优势

### ✅ 五大核心优势

| 优势 | 说明 |
|------|------|
| **单盘增量** | 无需成组添加，降低扩容门槛 |
| **在线操作** | 扩容全程存储池可读写，业务不中断 |
| **冗余保持** | 扩容后容错级别不变（RAIDZ2→RAIDZ2） |
| **中断恢复** | 支持重启/export/import后继续 |
| **成本最优** | 按需扩容，避免资源浪费 |

### ⚠️ 注意事项

| 注意点 | 说明 |
|--------|------|
| **不可逆操作** | 一旦开始扩展，无法撤销 |
| **容量折损** | 旧数据块存在headroom loss（可恢复） |
| **单VDEV限制** | 仅支持单RAIDZ VDEV池扩展 |
| **版本要求** | 需OpenZFS 2.3+，特性标志启用 |

## 使用场景

### 场景1：家庭用户增量扩容

**背景**：
- 4盘位NAS，使用3×4TB组成RAIDZ1
- 当前可用容量：8TB
- 数据增长需扩容至12TB

**方案**：
```bash
# 添加第4块4TB硬盘
zpool attach tank raidz1-0 /dev/sdd

# 扩容结果
- 新容量：12TB（+4TB增量）
- 扩容时间：约2-4小时（取决于数据量）
- 业务中断：0分钟
```

### 场景2：工作室弹性扩容

**背景**：
- 8盘位NAS，使用5×8TB组成RAIDZ2
- 当前可用容量：24TB
- 业务增长需扩容至32TB

**方案**：
```bash
# 添加第6块8TB硬盘
zpool attach tank raidz2-0 /dev/sdf

# 新容量：32TB（+8TB）
# 扩容时间：约5-10小时
```

### 场景3：企业合规存储扩展

**背景**：
- 需保留历史数据完整性
- 合规要求不可删除旧数据
- 存储容量紧张

**方案**：
- 使用RAIDZ扩展逐步增加容量
- WriteOnce保护关键数据
- 扩容过程数据完整性不变

## 操作步骤

### 准备阶段

#### 1. 检查系统要求

```bash
# 检查ZFS版本（需2.3+）
zfs version

# 检查特性标志状态
zpool get feature@raidz_expansion tank

# 输出应为 enabled 或 active
```

#### 2. 启用特性标志（如未启用）

```bash
# 升级存储池
zpool upgrade tank

# 验证特性启用
zpool get feature@raidz_expansion tank
# 输出: enabled
```

#### 3. 健康检查

```bash
# 检查池状态
zpool status tank

# 确认状态为 ONLINE
# 确认无 resilver/scrub 进行中

# 检查磁盘健康
zpool list -v tank
```

### 执行扩展

#### 4. 添加新磁盘

```bash
# 确认新磁盘可用
lsblk | grep sdX

# 执行扩展命令
zpool attach tank raidz2-0 /dev/sdX

# 命令说明：
# tank: 存储池名称
# raidz2-0: 目标VDEV名称
# /dev/sdX: 新磁盘设备路径
```

#### 5. 监控扩展进度

```bash
# 查看扩展状态
zpool status tank

# 输出示例：
pool: tank
state: ONLINE
expand: raidz expansion in progress, 45.2% complete

config:
    NAME        STATE     READ WRITE CKSUM
    tank        ONLINE       0     0     0
      raidz2-0  ONLINE       0     0     0
        sda     ONLINE       0     0     0
        sdb     ONLINE       0     0     0
        sdc     ONLINE       0     0     0
        sdd     ONLINE       0     0     0
        sde     ONLINE       0     0     0  (expanding)
```

#### 6. 等待完成

```bash
# 持续监控（可选）
watch -n 60 'zpool status tank'

# 扩展完成标志：
# - expand 行消失
# - 新盘状态变为 ONLINE
# - 容量增加
```

### 完成验证

#### 7. 验证扩容结果

```bash
# 检查新容量
zpool list tank

# 输出示例：
NAME   SIZE   ALLOC   FREE   EXPANDSZ
tank   24T    12T     12T    -

# 执行数据校验（建议）
zpool scrub tank
```

## 注意事项与风险提示

### ⚠️ 重要警告

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| **不可逆** | 扩展一旦开始无法撤销 | 确认需求后再操作 |
| **容量折损** | 旧数据块存在空间折损 | 随数据更新逐步恢复 |
| **性能影响** | 扩展期间IO性能下降10-20% | 选择业务低峰期 |
| **单VDEV** | 仅支持单RAIDZ VDEV池 | 多VDEV池需其他方案 |

### 容量折损详解

**原因**：旧数据块保持原有奇偶比分布到更多磁盘

| 配置变化 | 理论容量 | 报告容量 | 折损率 |
|----------|----------|----------|--------|
| 4盘RAIDZ2→5盘 | 3×D | 2×D(旧) | ~33% |
| 5盘RAIDZ2→6盘 | 4×D | 3×D(旧) | ~25% |
| 6盘RAIDZ2→7盘 | 5×D | 4×D(旧) | ~20% |

**恢复方法**：
```bash
# 方法1：自然恢复（随数据修改自动释放）

# 方法2：主动恢复（复制重写）
zfs send tank/data@snap | zfs recv tank/data_new
zfs destroy tank/data
zfs rename tank/data_new tank/data
```

## 常见问题FAQ

### Q1: 扩展需要多长时间？

**答**：取决于数据量和硬件性能：

| 数据量 | HDD耗时 | SSD耗时 |
|--------|---------|---------|
| 1TB | 30-60分钟 | 10-20分钟 |
| 10TB | 5-10小时 | 2-4小时 |
| 100TB | 50-100小时 | 20-40小时 |

### Q2: 扩展过程中可以读写数据吗？

**答**：可以。扩展全程存储池保持在线可读写状态，但性能可能下降10-20%。

### Q3: 扩展中途断电怎么办？

**答**：支持中断恢复。重启或重新import池后，扩展会自动从断点继续。

### Q4: 可以多次扩展吗？

**答**：可以。RAIDZ VDEV支持多次扩展，每次扩展都会改变奇偶比。

### Q5: 新磁盘容量必须和现有盘一致吗？

**答**：建议一致。新盘容量≥现有盘即可，但容量不一致会导致空间浪费。

### Q6: 如何取消扩展？

**答**：无法取消。扩展是不可逆操作，一旦开始必须完成。

### Q7: 多VDEV池可以扩展吗？

**答**：不支持。仅支持单RAIDZ VDEV池扩展。多VDEV池需添加新VDEV。

### Q8: nas-os什么时候支持RAIDZ扩展？

**答**：当前使用btrfs后端，支持RAID1/RAID10扩容。ZFS后端RAIDZ扩展正在规划中（P0优先级）。
