# RAIDZ 扩容成本分析报告

> 更新日期: 2026-04-02 | 编制: 户部

---

## 一、背景与目标

OpenZFS 2.3 引入的 RAIDZ Expansion 特性允许向现有 RAIDZ VDEV 单盘扩容，相比传统整组扩容方式，可大幅降低硬件投入门槛。本报告从财务角度分析两种扩容方式的成本差异，为用户提供决策依据。

---

## 二、扩容方式对比

### 2.1 扩容场景定义

**基准配置**: 5盘 RAIDZ2 (4TB × 5)，可用容量约 12TB

| 扩容目标 | 可用容量 | 新增磁盘 |
|---------|----------|----------|
| +20% | ~14.4TB | 单盘扩容 |
| +100% | ~24TB | 整组扩容 |

### 2.2 两种扩容方式

| 方式 | 操作 | 磁盘需求 | 特点 |
|------|------|----------|------|
| **单盘扩容** | `zpool attach` | 1盘 | RAIDZ Expansion，增量扩容 |
| **整组扩容** | `zpool add` | 一组新VDEV | 传统方式，成倍扩容 |

### 3.2 单盘扩容成本

**场景: 5盘 RAIDZ2 → 6盘 RAIDZ2**

| 项目 | 数值 | 说明 |
|------|------|------|
| 新增磁盘 | 1 × 4TB | ¥450 |
| 机箱扩展 | ¥0-200 | 如有空位则免费 |
| **硬件总成本** | **¥450-650** | 单盘扩容 |

**容量增益计算**:
```
原始: 5盘 RAIDZ2 = (5-2) × 4TB = 12TB 可用
扩展: 6盘 RAIDZ2 = (6-2) × 4TB = 16TB 可用（理论）
实际: 约 14TB（考虑容量折损）
增益: +2TB 可用容量
```

**单位成本**: ¥225-325 / TB

### 3.3 整组扩容成本

**场景: 5盘 RAIDZ2 → 10盘 (添加新raidz2-1)**

| 项目 | 数值 | 说明 |
|------|------|------|
| 新增磁盘 | 5 × 4TB | ¥2,250 |
| 机箱扩展 | ¥500-1,000 | 5盘位扩展 |
| **硬件总成本** | **¥2,750-3,250** | 整组扩容 |

**容量增益计算**:
```
原始: raidz2-0 = 12TB 可用
新增: raidz2-1 = 12TB 可用
总容量: 24TB 可用
增益: +12TB 可用容量
```

**单位成本**: ¥229-271 / TB

### 3.4 成本对比汇总

| 扩容方式 | 硬件投入 | 容量增益 | 单位成本 | 扩容比例 |
|---------|----------|----------|----------|----------|
| 单盘扩容 | ¥450-650 | +2TB | ¥225-325/TB | +16.7% |
| 整组扩容 | ¥2,750-3,250 | +12TB | ¥229-271/TB | +100% |

**关键发现**:
- 单位TB成本相近（差异<15%）
- 单盘扩容适合小幅度扩容（<30%）
- 整组扩容适合大幅度扩容（>50%）

## 五、风险差异分析

### 5.1 扩容过程风险

| 风险类型 | 单盘扩容 | 整组扩容 |
|---------|----------|----------|
| **数据丢失风险** | 低（保持冗余） | 低（新建VDEV） |
| **操作不可逆** | ⚠️ 不可回退 | 可分离VDEV |
| **容量折损** | ⚠️ 20-33%折损 | 无折损 |
| **磁盘故障处理** | 扩展暂停→修复→继续 | 不影响其他VDEV |

### 5.2 容量折损详解

**单盘扩容容量折损**:

```
扩展前: 4盘 RAIDZ2 → 奇偶比 2数据:2校验
扩展后: 5盘 RAIDZ2 → 奇偶比 3数据:2校验

旧数据块仍按旧奇偶比分布，导致"容量折损"
折损率 = 1 - (N_new-P)/(N_old-P) × (N_old/N_new)
```

| 扩展配置 | 折损率 | 恢复方式 |
|---------|--------|----------|
| 4→5盘 RAIDZ2 | ~33% | 数据重写/自然迁移 |
| 5→6盘 RAIDZ2 | ~25% | 数据重写/自然迁移 |
| 6→7盘 RAIDZ2 | ~20% | 数据重写/自然迁移 |

### 5.3 风险量化评估

| 评估维度 | 单盘扩容 | 整组扩容 | 说明 |
|---------|----------|----------|------|
| 操作风险 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 不可逆性 |
| 数据风险 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 冗余不变 |
| 容量风险 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 折损问题 |
| 时间风险 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 扩展耗时 |

## 六、成本决策矩阵

### 6.1 扩容规模决策

| 目标扩容比例 | 推荐方式 | 理由 |
|-------------|----------|------|
| **<20%** | 单盘扩容 | 成本最优，无需机箱扩展 |
| **20-40%** | 单盘扩容×2 | 两次扩展，逐步增长 |
| **40-100%** | 视情况 | 评估机箱空间 |
| **>100%** | 整组扩容 | 成本效益更好 |

### 6.2 机箱空间决策

| 机箱状态 | 推荐方式 | 理由 |
|---------|----------|------|
| **有空位** | 单盘扩容 | 无额外机箱成本 |
| **无空位** | 整组扩容+新机箱 | 或扩展机箱后单盘扩容 |
| **受限环境** | 单盘扩容 | 空间限制时唯一选择 |

### 6.3 预算约束决策

| 预算级别 | 推荐方式 | 说明 |
|---------|----------|------|
| **低预算 (<¥500)** | 单盘扩容 | 最小投入 |
| **中预算 (¥500-2000)** | 单盘扩容×2-3 | 分批投入 |
| **高预算 (>¥2000)** | 整组扩容 | 一步到位 |

## 八、成本优化建议

### 8.1 分阶段扩容策略

```
阶段1: 单盘扩容 (低成本验证)
   ↓ 观察3个月
阶段2: 评估是否继续单盘或转向整组
   ↓
阶段3: 根据业务增长决定最终方案
```

### 8.2 机箱规划建议

| 预期扩容 | 机箱选择 | 说明 |
|---------|----------|------|
| +1-2盘 | 现有空位即可 | 单盘扩容 |
| +3-5盘 | 8盘位机箱 | 预留空间 |
| +6+盘 | 12盘位机箱 | 长期规划 |

### 8.3 硬盘采购建议

1. **批量采购**: 3盘以上建议批量采购，可获5-10%折扣
2. **型号一致**: 扩容盘与原盘型号一致，避免兼容问题
3. **容量匹配**: 扩容盘容量≥原盘容量，充分利用空间

## 九、总结与建议

### 9.1 成本对比结论

| 维度 | 单盘扩容 | 整组扩容 | 结论 |
|------|----------|----------|------|
| **硬件成本** | ¥450-650 | ¥2,750-3,250 | 单盘投入小 |
| **单位TB成本** | ¥225-325 | ¥229-271 | 相近 |
| **时间成本** | 3-28小时 | 1小时 | 整组更优 |
| **容量折损** | 20-33% | 无 | 整组更优 |
| **风险级别** | 中（不可逆） | 低 | 整组更优 |
| **灵活性** | 高 | 中 | 单盘更优 |

### 9.2 推荐决策

| 用户场景 | 推荐方式 | 理由 |
|---------|----------|------|
| **家庭用户** | 单盘扩容 | 预算有限，小规模扩容 |
| **小型办公** | 单盘扩容 | 渐进式增长，灵活性高 |
| **中型企业** | 按需选择 | 评估机箱空间和预算 |
| **大型集群** | 整组扩容 | 规模效益，成本最优 |

### 9.3 关键建议

1. **小规模扩容优先单盘** - 投入小、门槛低
2. **大规模扩容选整组** - 成本效益更优
3. **预留机箱空间** - 降低扩容摩擦成本
4. **关注容量折损** - 扩展后主动重写数据恢复容量

## 十、附录：成本计算工具

### 10.1 单盘扩容成本公式

```
硬件成本 = 单盘价格 + 机箱扩展成本(如需要)

容量增益 = (N_new - P) × DiskSize - (N_old - P) × DiskSize
         = (N_new - N_old) × DiskSize

单位成本 = 硬件成本 / 容量增益
```

### 10.2 整组扩容成本公式

```
硬件成本 = 组磁盘数 × 单盘价格 + 机箱扩展成本

容量增益 = 组磁盘数 × DiskSize - P × DiskSize
         = (组磁盘数 - P) × DiskSize

单位成本 = 硬件成本 / 容量增益
```

### 10.3 容量折损估算

```
折损率 ≈ 1 - 新数据比例 × (N_new - P) / (N_old - P)

新数据比例随时间增加，折损逐渐降低
```
