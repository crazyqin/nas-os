## 1. 概述

本文档分析NAS-OS中引入LXC沙箱的资源消耗与运营成本。基于户部定价模型，对CPU、内存、存储、网络四维度进行量化分析。

**定价基准**（源自 `app-cost-analysis.md`）：
- CPU: ¥0.05/核/小时
- 内存: ¥0.02/GB/小时
- 存储(HDD): ¥0.15/GB/月 | 存储(SSD): ¥0.50/GB/月
- 网络出流量: ¥0.80/GB（月100GB免费额度）

## 2. CPU成本分析

### 2.1 LXC CPU开销特征

LXC共享宿主内核，CPU开销低于VM但高于裸机Docker：

| 开销来源 | 裸机Docker | LXC沙箱 | 虚拟机(VM) |
|---------|-----------|---------|-----------|
| 内核调度 | 0% | 0% | 3-8% |
| cgroup管理 | <1% | <1% | N/A |
| 命名空间隔离 | <1% | <1% | N/A |
| I/O模拟 | 0% | 0% | 5-15% |
| **总CPU开销** | **<1%** | **~2%** | **8-23%** |

### 2.2 CPU限额对性能的影响

| CPU限额 | 性能基准(满核=100) | 实际可用 | 适合工作负载 |
|--------|-------------------|---------|------------|
| 0.5核 | ~48% | ~48计算单位 | 轻量服务、API网关 |
| 1核 | ~96% | ~96计算单位 | Web应用、小型数据库 |
| 2核 | ~192% | ~190计算单位 | 编译构建、中型服务 |
| 4核 | ~384% | ~375计算单位 | 数据处理、AI推理 |
| 8核 | ~768% | ~745计算单位 | 高性能计算 |

> **关键发现**: LXC沙箱CPU开销约2%，在高负载时可忽略。建议通过cgroup `cpu.cfs_quota_us` 精确限制。

## 7. 优化建议

### 7.1 成本优化

| 优化措施 | 预期节省 | 实施难度 |
|---------|---------|---------|
| 非活跃沙箱自动休眠 | 30-50% | 中 |
| ZFS压缩(lz4/zstd) | 20-30%存储 | 低 |
| 去重存储 | 10-20%存储 | 中 |
| 分时复用CPU | 20-40% | 高 |
| 快照合并策略 | 10-15%存储 | 低 |

### 7.2 架构建议

1. **共享rootfs**: 多个沙箱共享只读基础镜像层，存储节省可达60%+
2. **内存balloon**: 低负载时自动回收空闲内存至宿主
3. **冷热分层**: 热数据SSD + 冷数据HDD自动分层
4. **沙箱池化**: 预热沙箱池，按需分配，减少启动开销

**核心结论**：
- LXC沙箱总开销约2-5%，远低于VM(15-30%)

- 网络开销极小，不构成成本瓶颈
