**版本**: v2.326.0 | **日期**: 2026-03-30

## 一、TrueNAS RAIDZ Expansion技术分析

### 1.1 技术背景
- **开发周期**: 约3年
- **资金投入**: 约$100,000
- **核心开发者**: Matt Ahrens (ZFS联合创始人)
- **技术基础**: OpenZFS 2.3原生支持

### 1.2 核心特性
| 特性 | 说明 | 价值 |
|------|------|------|
| 在线扩展 | 扩容过程存储池保持可用 | 业务不中断 |
| 单盘添加 | 每次添加一块磁盘 | 降低扩容门槛 |
| 保持冗余 | RAIDZ1/2/3级别不变 | 数据安全保障 |
| 自动重分布 | 数据自动条带化 | 空间均衡利用 |
| 中断恢复 | 支持重启后继续 | 扩容过程可中断 |

### 1.3 性能优化 (Fangtooth)
- HDD阵列: 5倍加速 (典型情况)
- 最大可达: 10倍加速
- 测试数据: 6.38GB数据在4分31秒内完成重分布

## 二、nas-os存储架构现状

### 2.1 现有技术栈
- **文件系统**: btrfs为主
- **RAID支持**: RAID0/RAID1/RAID10/RAID5/RAID6
- **存储池**: 基于btrfs多设备管理

### 2.2 扩容现状
- **当前方式**: 新建存储池 + 手动迁移
- **痛点**: 
  - 扩容需完整数据备份迁移
  - 过程耗时，业务中断时间长
  - 空间利用率提升需重建池

## 三、nas-os RAIDZ扩展方案设计

### 3.1 技术路线评估

| 方案 | 适用场景 | 开发成本 | 稳定性 | 实现周期 |
|------|----------|----------|--------|----------|
| btrfs优化封装 | RAID1/RAID10 | 低 | 高 | 2-3个月 |
| 引入ZFS后端 | RAIDZ企业级 | 高 | 最高 | 6-12个月 |
| 混合双引擎 | 全场景覆盖 | 中 | 中 | 3-6个月 |

### 3.2 推荐方案: btrfs优化封装 (短期)

**阶段一**: RAID1/RAID10扩容自动化
- 封装 `btrfs device add` + `btrfs balance`
- WebUI扩容进度监控
- 中断恢复机制设计

**阶段二**: ZFS可选后端 (中期)
- 企业用户可选ZFS后端
- RAIDZ Expansion原生支持
- btrfs→ZFS迁移工具

### 3.3 关键实现点
1. **设备添加**: `btrfs device add /dev/sdX /mnt/pool`
2. **数据重平衡**: `btrfs balance start -dconvert=raid1 /mnt/pool`
3. **进度监控**: `btrfs balance status /mnt/pool`
4. **空间检查**: 扩容前容量预警

## 四、WebUI设计流程

```
[存储池详情] → [扩容按钮] → [选择新磁盘]
    → [容量预估] → [确认扩容] → [进度显示]
    → [扩容完成]
```

### 4.1 API接口设计
- `POST /api/v1/storage/pools/{id}/expand` - 启动扩容
- `GET /api/v1/storage/pools/{id}/expand/status` - 查询进度
- `DELETE /api/v1/storage/pools/{id}/expand` - 取消扩容
