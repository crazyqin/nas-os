# 文件锁定安全设计文档

## 概述

本文档分析文件锁定机制的安全设计，对标群晖Drive文件锁定功能，确保防止死锁和权限兼容。

## 安全威胁分析

### 1. 死锁风险
- **场景**: 多用户同时锁定同一文件的不同部分
- **风险**: 锁定顺序不一致导致死循环等待
- **缓解**: 采用超时机制和锁升级检测

### 2. 权限冲突
- **场景**: 低权限用户锁定高权限文件
- **风险**: 权限提升攻击或数据泄露
- **缓解**: 锁定前强制权限检查

### 3. 锁定滥用
- **场景**: 用户恶意锁定大量文件
- **风险**: 系统资源耗尽
- **缓解**: 锁定数量配额限制

## 安全设计原则

### 1. 最小权限原则
- 锁定操作需要文件写入权限
- 只锁定必要范围（全文件/部分区域）
- 锁定后权限不可提升

### 2. 超时机制
- 默认锁定超时: 30分钟
- 最大锁定时长: 24小时
- 强制释放机制: 超时自动解锁

### 3. 死锁预防
- 锁定顺序: 按文件路径字典序
- 锁升级检测: 不允许读锁升级为写锁
- 等待队列: 按请求时间排序

## 锁定类型

### Advisory Lock（建议锁）
- POSIX fcntl/FLOCK风格
- 协议约定，非强制
- 适用场景: 协作编辑

### Mandatory Lock（强制锁）
- 内核级强制执行
- 阻止未授权访问
- 适用场景: 敏感数据保护

## API设计

### 锁定请求
```json
POST /api/v1/files/lock
{
  "path": "/share/docs/report.pdf",
  "type": "exclusive",  // exclusive/shared
  "timeout": 1800,      // 秒
  "reason": "编辑中"
}
```

### 锁定响应
```json
{
  "lock_id": "lock-12345",
  "status": "granted",
  "expires_at": "2026-04-03T14:00:00Z",
  "locked_by": "user@example.com"
}
```

### 解锁请求
```json
DELETE /api/v1/files/lock/lock-12345
```

## 实现建议

### 存储层
- 使用ZFS文件系统属性存储锁信息
- 锁状态持久化到数据库
- 支持NFS/SMB锁定协议映射

### 应用层
- 锁管理服务（LockManager）
- 分布式锁支持（Redis/etcd）
- 锁状态通知机制（WebSocket）

### 监控层
- 锁定统计Dashboard
- 异常锁定告警
- 锁冲突审计日志

## 最佳实践

1. **编辑前锁定**: 打开文件前请求锁
2. **定期续锁**: 长时间编辑需续期
3. **退出必解锁**: 会话结束时释放
4. **冲突处理**: 锁冲突时提示用户协商

## 与现有权限体系兼容

nas-os现有权限体系:
- SMB权限映射
- LDAP/AD用户认证
- RBAC角色管理

锁定机制需:
- 继承文件ACL权限检查
- 与用户会话绑定
- 支持管理员强制解锁
