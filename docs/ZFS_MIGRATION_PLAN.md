**版本**: v1.0.0

## 1. 概述

本文档定义了从 btrfs 到 ZFS 的迁移路线图，包括迁移策略、技术方案、风险评估和时间表。

### 1.1 迁移动机

| 因素 | btrfs 现状 | ZFS 优势 |
|------|------------|----------|
| RAID5/6稳定性 | ⚠️ 官方标记不稳定 | ✅ 生产级稳定 |
| 数据完整性 | 基于校验和 | 端到端校验+自我修复 |
| 扩容能力 | 需balance操作 | RAIDZ Expansion原生支持 |
| 快照性能 | 中等 | 高效增量快照 |
| 企业特性 | 基础 | 同步复制、压缩、去重 |

### 1.2 目标用户群

- **企业用户**: 需要最高数据可靠性保证
- **大容量存储**: 50TB+ 存储池，需要RAID5/6
- **数据敏感场景**: 金融、医疗、法律等行业
- **混合场景**: 需要分层存储和智能缓存

    // ... 统一接口

## 3. 迁移策略

### 3.1 迁移场景分类

| 场景 | 策略 | 工具 | 数据丢失风险 |
|------|------|------|--------------|
| 新安装 | 直接使用ZFS | 安装程序 | 无 |
| 小容量迁移 | 全量备份恢复 | zfs send/recv | 低 |
| 大容量迁移 | 增量同步 | zfs replication | 低 |
| 无停机迁移 | 双写切换 | 自研工具 | 中 |

### 3.2 推荐迁移流程

#### 方案A: 新安装直接使用ZFS (推荐)

```
1. 全新安装 nas-os
2. 安装时选择 ZFS 后端
3. 创建 RAIDZ 池
4. 导入数据 (从备份或外部存储)
```

#### 方案B: 从btrfs迁移到ZFS

```
┌────────────────────────────────────────────────────────────┐
│                    btrfs → ZFS 迁移流程                      │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  阶段1: 准备 (预计 2-4 小时)                                │
│  ├─ 确认目标磁盘数量和容量                                   │
│  ├─ 安装 ZFS 内核模块                                       │
│  ├─ 创建临时 ZFS 池 (目标磁盘)                               │
│  └─ 配置网络 (如需远程同步)                                  │
│                                                            │
│  阶段2: 数据迁移 (取决于数据量)                              │
│  ├─ 全量同步: zfs send/recv 或 rsync                       │
│  │   └─ 预估速度: 100-500 MB/s (HDD), 500-1000 MB/s (SSD) │
│  ├─ 增量同步: 定期同步差异数据                               │
│  └─ 数据校验: checksum 验证                                 │
│                                                            │
│  阶段3: 切换 (预计 1-2 小时)                                 │
│  ├─ 停止所有服务                                            │
│  ├─ 最后一次增量同步                                        │
│  ├─ 卸载 btrfs 池                                           │
│  ├─ 导入 ZFS 池                                             │
│  └─ 重启服务验证                                            │
│                                                            │
│  阶段4: 清理 (可选)                                         │
│  ├─ 格式化旧 btrfs 磁盘                                     │
│  └─ 添加到 ZFS 池作为扩展                                    │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

#### 方案C: 混合双池 (过渡方案)

```
1. 保留现有 btrfs 池
2. 新增 ZFS 池 (新磁盘)
3. 数据逐步迁移到 ZFS 池
4. 最终弃用 btrfs 池
```

### 3.3 迁移时间估算

| 数据量 | HDD (100MB/s) | SSD (500MB/s) | NVMe (1000MB/s) |
|--------|---------------|---------------|-----------------|
| 1TB | 3小时 | 40分钟 | 20分钟 |
| 10TB | 30小时 | 6小时 | 3小时 |
| 50TB | 150小时 | 30小时 | 15小时 |
| 100TB | 300小时 | 60小时 | 30小时 |

**注**: 实际时间受文件数量、网络带宽、压缩算法影响。

## 4. 风险评估

### 4.1 技术风险

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| ZFS内核模块兼容性 | 中 | 提供预编译模块，支持主流内核 |
| 许可证问题 (CDDL/GPL) | 低 | ZFS作为可选模块，用户自行安装 |
| 内存占用高 | 中 | 建议最小8GB，推荐16GB+ |
| 迁移过程数据丢失 | 高 | 强制备份，增量同步，校验验证 |
| 学习曲线 | 低 | 提供详细文档和迁移助手 |

### 4.2 业务风险

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 服务中断时间 | 中 | 选择低峰时段，提供增量迁移 |
| 用户操作失误 | 高 | 迁移向导、确认步骤、回滚机制 |
| 硬件兼容性 | 低 | 支持主流硬件，HCL列表 |

### 4.3 风险缓解策略

```
1. 备份优先原则
   - 迁移前必须完整备份
   - 保留原数据直到验证完成

2. 分阶段验证
   - 迁移完成后数据校验
   - 服务功能测试
   - 性能基准测试

3. 回滚机制
   - 保留 btrfs 池至少1周
   - 提供一键回滚脚本

4. 用户教育
   - 迁移前评估问卷
   - 风险提示和确认
   - 详细操作文档
```
